# The calls server

Everything of Zaki Workspace lives under the workspace's own domain (the owner's rule, 2026-10-26): the calls
server is `calls.workspace.zakiai.io` (it was `calls.zakiai.io` for its first day).

Voice and video calls run on **LiveKit** (Apache-2.0, free), self-hosted on the owner's server as its own
Coolify service — no paid API, no third party in the media path. Set up on 2026-10-25.

| | |
|---|---|
| Coolify | project «Zaki workspace» → production → service **`zaki-calls`** |
| Image | `livekit/livekit-server:v1.13.9` (pinned; raise it on purpose) |
| Signalling | `https://calls.workspace.zakiai.io` → container port 7880, through Coolify's proxy (TLS on 443) |
| Media | TCP **7881** (ICE over TCP) and UDP **7882** (one muxed port), published straight on the host |
| Strict networks | TURN at `turn.workspace.zakiai.io:443` (TLS by Coolify's proxy) and UDP **3478** |
| Keys | generated by Coolify for the service (`SERVICE_USER_LIVEKIT`, `SERVICE_PASSWORD_64_LIVEKIT`), never typed, never in this repository |

The app needs three variables (Coolify → `zaki-workspace` → Environment Variables):
`LIVEKIT_URL=wss://calls.workspace.zakiai.io`, `LIVEKIT_API_KEY` = the service's `SERVICE_USER_LIVEKIT`,
`LIVEKIT_API_SECRET` = its `SERVICE_PASSWORD_64_LIVEKIT`. Without them the app still runs; the call button
answers «خادم المكالمات مش جاهز».

The compose file of the service (the settings file is kept by Coolify under the service's Persistent Storage):

```yaml
services:
  livekit:
    image: 'livekit/livekit-server:v1.13.9'
    restart: unless-stopped
    command: ['--config', /etc/livekit.yaml]
    environment:
      - SERVICE_FQDN_LIVEKIT_7880
      - 'LIVEKIT_KEYS=${SERVICE_USER_LIVEKIT}: ${SERVICE_PASSWORD_64_LIVEKIT}'
    volumes:
      - type: bind
        source: ./livekit.yaml
        target: /etc/livekit.yaml
        content: |
          port: 7880
          rtc:
            tcp_port: 7881
            udp_port: 7882
            node_ip: <the server's public IP>
          turn:
            enabled: true
            domain: turn.workspace.zakiai.io
            tls_port: 443
            external_tls: true
            udp_port: 3478
    ports:
      - '7881:7881/tcp'
      - '7882:7882/udp'
      - '3478:3478/udp'
    labels:
      - traefik.enable=true
      - 'traefik.tcp.routers.zk-turn.rule=HostSNI(`turn.workspace.zakiai.io`)'
      - traefik.tcp.routers.zk-turn.entrypoints=https
      - traefik.tcp.routers.zk-turn.tls=true
      - traefik.tcp.routers.zk-turn.tls.certresolver=letsencrypt
      - traefik.tcp.routers.zk-turn.service=zk-turn
      - traefik.tcp.services.zk-turn.loadbalancer.server.port=443
```

**The way out for strict networks (TURN, since 2026-10-26).** A network that lets through only ordinary web traffic
(a company, a hotel, some mobile networks) still carries a call: LiveKit's own TURN server answers at
`turns:turn.workspace.zakiai.io:443`. Coolify's proxy holds the certificate (Let's Encrypt, by SNI) and hands the plain
stream to LiveKit (`external_tls`); TURN over UDP answers on 3478. LiveKit hands these to every browser by itself;
the app changes nothing, and the browser uses them only when the direct way is closed.

How the app uses it (`src/server/calls/`): the server signs a two-minute pass for one person and one call
(`POST /api/calls/[id]/token`) only after `src/server/policy/call.ts` says they may join; it asks the calls
server who is in a room (to end an empty call) and takes a removed person out (its RoomService API). Nothing
about the sound or the picture is stored.

- ⚠️ LiveKit logs that the host's UDP receive buffer is small. 🔧 With many calls at once, raise
  `net.core.rmem_max` / `net.core.rmem_default` on the host to 5000000.
- ⚠️ A removed person's pass stays valid for at most two minutes. 🔧 The seat is marked removed, so no new pass
  is issued, and the person is taken out of the room at once; a reconnect inside those two minutes is the
  window that remains.
